# Humanier Destructible Terrain

`com.humanier.terrain` is an embedded UPM package for continuous, editable terrain. It uses a deterministic signed-density field sampled in 32-cube chunks at a default 0.5 m cell size. Burst-compiled Transvoxel mesh jobs produce a smooth low-poly surface and allow caves, tunnels, overhangs, digging, filling, and flattening.

## Use

Create a `TerrainWorld` GameObject and assign a `TerrainWorldSettings` asset. Set a camera or player transform as its focus. Call `RequestEdit` with `TerrainEditRequest.Dig`, `Fill`, or `Flatten`. Edits accept radii from 0.1 through 64 metres and return a `TerrainEditHandle` that reports completion progress. Fill requests can set `maxAddedSolidVolume` (cubic metres) to cap added soil; the world reduces brush strength uniformly until the cap fits. The handle exposes `DataCommitted`, `RemovedSolidVolume`, and `AddedSolidVolume` after the density transaction commits. Volume accounting uses clamped sample occupancy (`0.5 + density / voxelSize`) and counts each global border sample once.

For the included scene, run `Humanier > Terrain > Create Demo Scene` in the Unity Editor. The created explorer camera uses the mouse to target terrain, left click to apply the selected brush, number keys `1` through `3` to select dig/fill/flatten, and the wheel to set a 0.5–64 m brush radius.

`SampleBiome`, `SampleSurfaceHeight`, `SampleDensity`, `TrySampleDensity`, `SampleGeneratedDensity`, `TryRaycast`, `IsCollisionReady`, `SetOriginOffset`, and `TryResumeCacheWrites` are public query/control APIs. `SampleDensity` is authoritative and includes cached edits for unloaded chunks; use `SampleGeneratedDensity` when the original seeded field is needed. `TrySampleDensity` reports a cache-read failure without silently returning generated terrain. An edit stages every affected chunk before writing, so a cache or capacity failure leaves all densities unchanged. Its density and material writes commit atomically before mesh waits; if the world is disabled or destroyed afterward, the handle may be `Cancelled` while retaining `DataCommitted` and its volume accounting. A handle becomes `Completed` after its density is committed and every affected resident chunk mesh is current; unloaded chunks are persisted and rebuild when streamed back in. With colliders enabled, resident meshes are also assigned to the colliders. Edits execute in request order. The writable density field stays package-internal, so edits always obey the bedrock and 60-metre protection rules.

## Low-poly appearance

The included `Humanier/Terrain Low Poly` shader defaults to geometric per-triangle lighting, including newly dug surfaces and LOD transition triangles. `TerrainWorldSettings.minimumMeshLod` can raise the minimum resident mesh stride without changing the authoritative density grid; the planet test scene uses LOD 1 for approximately 1 metre surface cells near the player. `facetDetailAmplitude` and `facetDetailSpacing` add deterministic, low-amplitude piecewise-planar height variation to generated terrain and Dig/Fill targets, so the geometry itself supplies small face-direction changes. Set the amplitude to 0 to restore the original surface. On the terrain material, `Facet Strength` controls the blend from smooth normals (0) to crisp facets (1). `Ambient Light` defaults to 0.3; increase it for softer contrast. `Brightness` controls overall intensity. The detail settings are part of terrain generation configuration and require a world reload when changed.

Material boundaries follow triangle edges: each regular and transition triangle uses its majority vertex material color. Three-way ties use a stable palette ordering. Only vertices that need a different face color are duplicated; positions, normals, density and material samples are preserved. Existing runtime meshes need rebuilding (or restarting Play Mode) to show this change. Coarser LODs can move the visible boundary by a face as the triangulation changes.

## Profiling edits

Use the Unity Profiler Timeline view and filter for `Terrain.Edit`. The edit pipeline exposes separate markers for candidate selection, chunk preparation, sample staging, fill-strength resolution, chunk write-plan construction, density commit, subscriber notification, and mesh queueing. Mesh job scheduling/completion and main-thread mesh/collider replacement use `Terrain.Mesh.*`, `Terrain.ApplyCompletedMeshes`, and `Terrain.AssignMesh`, which makes mineral/ecology callbacks, collider cooking, and upload spikes distinguishable from brush evaluation.

## Limits in 0.1.1

The current package provides distance-based mesh decimation with Transvoxel transition cells, bounded mesh jobs, incremental edit batching, bounded CPU chunk caching, and gzip session caching in `Application.temporaryCachePath`. Each `TerrainWorld` instance owns a unique cache namespace, so a fresh application session always regenerates the source world. Cache files are atomically replaced and are deleted with the world; they are session recovery data, not save-game persistence. Disabling a world cancels outstanding edits and releases queued mesh jobs; re-enabling it rebuilds only stale meshes. Cache write failures pause streaming and edits until `TryResumeCacheWrites` verifies the temporary cache is writable again.
