# Runtime architecture

`TerrainWorld` owns a FIFO edit queue and a finite set of active `TerrainChunkData` instances. Chunks use integer IDs and derive every sample position from the ID plus a local cell coordinate, which makes generation independent of load order and handles negative coordinates. `SetOriginOffset` shifts rendered mesh coordinates while preserving the deterministic global sample domain.

Each sample stores signed density and material. Positive density is solid, zero is the surface, and negative density is air. A modified chunk is saved through `TerrainSessionCache` before streaming eviction. Cache namespaces are generated per `TerrainWorld`, so reloads inside one runtime restore modifications while later application sessions begin from the seed.

Protected samples at the generated bedrock height and at least 60 metres under their original surface cannot be changed. Protection is evaluated for every brush write rather than using the edited density, so filling or digging never moves the floor.

`TerrainWorldSettings.facetDetailAmplitude` and `facetDetailSpacing` add deterministic piecewise-planar detail to generated surface columns and Dig/Fill targets. The detail is evaluated from global coordinates, so shared chunk borders and reloads use the same values. `minimumMeshLod` raises the minimum mesh stride for resident chunks without changing the authoritative density grid or volume accounting.

An edit first stages all candidate chunks and then evaluates affected global samples once. Sample staging walks the brush's grid-aligned sphere bounds, not every sample in every touched chunk; chunk write plans are likewise restricted to the brush AABB. Shared border samples are copied from one canonical global sample plan into every resident chunk that stores them, which keeps adjacent chunk densities coherent and prevents duplicate volume accounting. Solid occupancy is `Clamp01(0.5 + density / voxelSize)`; removed and added volume are the positive before/after occupancy deltas multiplied by `voxelSize^3`. A nullable `TerrainEditRequest.maxAddedSolidVolume` applies a cubic-metre budget. When a fill would exceed that budget, the runtime uses bisection to reduce the requested strength uniformly. Zero-budget fills are confirmed no-ops, including materials. `TerrainEditHandle.DataCommitted` is set only after all prepared writes have completed, before resident mesh work begins, so cancellation during mesh generation does not discard trustworthy accounting.

Edit performance is split into Unity Profiler markers under `Terrain.Edit.*`: candidate selection, per-chunk preparation, sample staging, fill-strength resolution, write-plan construction, density commit, subscriber notification, and mesh queueing. Mesh generation and main-thread replacement remain under `Terrain.Mesh.*`, `Terrain.ApplyCompletedMeshes`, and `Terrain.AssignMesh`, so CPU-side brush work, mineral/ecology callbacks, mesh upload, and collider cooking can be distinguished.
